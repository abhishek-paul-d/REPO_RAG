# Flask commit-search validation runbook

Repeat the winning `psf/requests` commit-search setup (`summary_fused_hidden`: summary-embedded commit index for search only, `agent_commit_query=fused`, `agent_commit_hide_summary=true`, `commit_explain` prompt) on `pallets/flask` to check whether the gain holds on a second repository.

**Targets and isolation**
- **Repository pin:** `pallets/flask` @ `d086db856be187255b8ec61ef409357393020f32` (`3,829` non-merge commits).
- **Questions:** `136` held-out test bug-to-fix pairs in `eval/datasets/agent_eval_commit_full_pallets__flask_v1.jsonl` (from `170` total pairs in `eval/datasets/phase5_bugfix_v2/repos/pallets__flask/pairs.jsonl`: `136` test, `34` dev).
- **Separate storage:** All Flask index data goes into `D:\Repo_chatbot\data_flask` and `data/exp_summaries_pallets__flask` (or another `--out` folder). The shipped `D:\Repo_chatbot\data` (`psf/requests`) index stays untouched.
- **No production default changes:** Nothing here changes defaults in `config.py`.
- **Time figures below are rough estimates (not measured on Flask).** Across all Colab steps, expect roughly 1.5–2.5 hours of GPU time total.

---

## Stage 1 — Index `pallets/flask` on Colab (T4 GPU)

`notebooks/index_flask_on_colab.ipynb` (generated by `notebooks/build_flask_index.py`) is preconfigured for Flask at `d086db856be187255b8ec61ef409357393020f32` with `SHALLOW_CLONE = False`, `INDEX_HISTORY = True`, `INDEX_PRS = False`, `DTYPE = "float32"`, and `COMMIT_EMBED_BATCH = 4` (auto-capped for GPUs under 30 GiB). A free T4 works (`float32` matches laptop query vectors and avoids slow emulated `bfloat16` on T4).

1. Upload `notebooks/index_flask_on_colab.ipynb` to Google Colab.
2. **Runtime -> Change runtime type -> T4 GPU** (an A100 is faster if available, not required).
3. **Runtime -> Run all.** Keep the browser tab open; commit embedding is the slow step (roughly 45–90 minutes on a T4, not measured).
4. Confirm the final cell downloads `repo_rag_index.zip` before closing the session, then **Runtime -> Disconnect and delete runtime**.

## Stage 2 — Import locally into `D:\Repo_chatbot\data_flask`

`D:\Repo_chatbot\data\phase5_repos\pallets__flask` is an existing `--no-checkout` full clone on disk (all git objects for `d086db856be1` are present locally, 0 files checked out). Cloning it locally with a checked-out working tree at `D:\Repo_chatbot\data_flask\repos\pallets__flask` keeps `phase5_repos` untouched, lets `repo-rag index-symbols` scan real files, and satisfies `build_agent("pallets/flask", ...)` (imported manifests clear `clone_path`).

From `D:\Repo_chatbot_quality`:

```powershell
$env:REPO_RAG_DATA_DIR = "D:\Repo_chatbot\data_flask"
git clone --no-hardlinks D:\Repo_chatbot\data\phase5_repos\pallets__flask D:\Repo_chatbot\data_flask\repos\pallets__flask
git -C D:\Repo_chatbot\data_flask\repos\pallets__flask checkout d086db856be187255b8ec61ef409357393020f32
uv run repo-rag import-index path\to\repo_rag_index.zip
uv run repo-rag index-history pallets/flask --checkout D:\Repo_chatbot\data_flask\repos\pallets__flask --ref d086db856be187255b8ec61ef409357393020f32 --offline
uv run repo-rag index-symbols pallets/flask --checkout D:\Repo_chatbot\data_flask\repos\pallets__flask
uv run repo-rag search "how does Flask push the request context" --repo pallets/flask --kind commits
```

Check the `index-history` output: it should report `Embedded 0; unchanged 3829` (confirming it built `D:\Repo_chatbot\data_flask\metadata.db` without re-embedding commits on the CPU).

## Stage 3 — Write 27B commit summaries for Flask (A100 40 GB)

### 3a. Prepare locally

```powershell
uv run python eval/summarize_commits.py --repo pallets/flask --data-dir D:\Repo_chatbot\data_flask prepare
```

This writes `eval/commit_summary_pilot/pallets__flask/all_commits.jsonl` (`3,829` commits) and `eval/commit_summary_pilot/pallets__flask/queries.jsonl` (up to `170` bug-fix pairs whose gold SHA is indexed).

### 3b. Start the 27B server notebook

1. Upload `notebooks/repo_rag_ask_source.zip` and `notebooks/serve_model_27b_on_colab.ipynb` to Drive (or upload the notebook directly in Colab and put `repo_rag_ask_source.zip` where it reads it; see [docs/COLAB_SESSION.md](COLAB_SESSION.md)). Note the current `notebooks/repo_rag_ask_source.zip` hash before uploading.
2. Run all on an **A100 40 GB** (`CONCURRENCY = 8`).
3. Confirm the printed health line says `decode_mode: cuda-graphs + mtp3`, `max_input_tokens: 12288`, and copy the tunnel `<url>` and `<token>`.

### 3c. Summarize and package

```powershell
uv run python eval/summarize_commits.py --repo pallets/flask run --url <url> --token <token> --workers 8
```

`run` appends to `eval/commit_summary_pilot/pallets__flask/summaries_27b.jsonl` and is resumable (roughly 30–45 minutes on an A100 at 8 workers, not measured; `psf/requests`'s 4,883 commits took ~45 minutes at 8 workers). When finished, verify and zip:

```powershell
uv run python eval/summarize_commits.py --repo pallets/flask status
uv run python eval/summarize_commits.py --repo pallets/flask package
```

If `status` reports any commits left (e.g., failed rows), re-run the `run` command above first; it retries missing rows automatically. `package` writes `eval/commit_summary_pilot/pallets__flask/all_input.zip`.

*(Optional optimization: if you want to run Stage 5 controls on the already-running 27B server before embedding summaries, you can run `--only control_a control_b` right here while the 27B server is hot; `commit_session.py` skips finished steps in `state.json` on re-run.)*

## Stage 4 — Embed summaries on Colab GPU & build the summary index

1. Release/stop the 27B server GPU if needed, then start a Colab GPU runtime for `notebooks/commit_summary_pilot_on_colab.ipynb` (A100 is fastest; a T4 also works — on T4, lower `DOC_BATCH` from `8` to `4` in the Parameters cell if memory is tight).
2. **Runtime -> Run all.** When prompted by `files.upload()`, upload `eval/commit_summary_pilot/pallets__flask/all_input.zip`.
3. Download `pilot_vectors.npz` (rename locally if desired, e.g. `flask_vectors.npz`), then disconnect the embedding runtime.
4. Score the vectors and build the Flask summary experiment index back on your laptop:

```powershell
uv run python eval/summarize_commits.py --repo pallets/flask score --vectors path\to\flask_vectors.npz
uv run python eval/summarize_commits.py --repo pallets/flask --data-dir D:\Repo_chatbot\data_flask build-index --vectors path\to\flask_vectors.npz
```

`build-index` copies `D:\Repo_chatbot\data_flask` to `D:\Repo_chatbot_quality\data\exp_summaries_pallets__flask` (via the shared `data` directory) and swaps only the Flask `commits` texts and vectors there. If you prefer to keep the summary copy next to `data_flask` instead, pass `--out D:\Repo_chatbot\data_flask_summaries`. Either way, `D:\Repo_chatbot\data_flask` is only read.

## Stage 5 — Run the 136-question Flask agent evaluation (A100 40 GB)

Start `notebooks/serve_model_27b_on_colab.ipynb` on an **A100 40 GB** (if not already running), confirm the health line, then run the 4-step confirmation (2 identical controls for noise + 2 repeats of the winning `summary_fused_hidden` setting):

```powershell
uv run python eval/commit_session.py `
  --repo pallets/flask `
  --data-dir D:\Repo_chatbot\data_flask `
  --url <url> --token <token> --workers 8 `
  --only control_a control_b summary_fused_hidden summary_fused_hidden_b
```

- If you used a custom `--out` path in Stage 4, also pass `--summary-index D:\Repo_chatbot\data_flask_summaries`.
- Add `fused` and `summary_hidden` to `--only` if you also want to separate the fusion-only and summary-only contributions on Flask.
- Finished steps are recorded in `eval/commit_session_results/pallets__flask/state.json` and skipped on resume.

When done, **disconnect and delete the Colab runtime**, then read:

- `eval/commit_session_results/pallets__flask/report.md` (strict/lenient scores out of `136`, won/lost vs `control_a`, two-sided sign-test `p`, control-to-control flips)
- `eval/commit_summary_pilot/pallets__flask/result_all.json` (dense and hybrid Hit@1/5/10/20 and MRR across all 170 dev+test pairs with vs without 27B summaries)

Compare against `psf/requests` (`eval/commit_session_results/report.md`, 113 test questions): `control_a/b/c` scored `76 / 76 / 78` strict (`76 / 76 / 79` lenient), while `summary_fused_hidden` / `_b` scored `82 / 84` strict (`83 / 85` lenient).
