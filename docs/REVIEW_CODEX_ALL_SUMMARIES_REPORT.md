## Recurring problems

The summaries often broaden a conditional fix into a guarantee. In row 4854, for example, the summary says that consumed content always triggers an error, but the new condition also checks for a boolean sentinel. Some summaries attribute implementation changes to a changelog or test edit, as in row 4680. Version bumps attract unsupported claims such as “latest stable release,” and build, test and presentation changes attract unsupported claims about speed, reliability and readability.

## Recommendation

Blank the 902 wrong summaries before using this dataset in any index. Rewrite the entries for substantive changes, especially runtime fixes, API changes and compatibility changes, using the commit evidence to preserve the exact affected path and conditions. Leave empty commits, whitespace-only edits, contributor-list updates and cosmetic documentation changes without generated summaries. For a mechanical version bump, rely on the version metadata unless the supplied text documents a substantive release change.
